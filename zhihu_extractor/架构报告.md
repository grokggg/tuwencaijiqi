# 知乎付费文章内容获取系统 v2.0 — 架构报告

## 1. 系统概述

本系统是一个模块化、自适应的内容获取工具，专门用于在受限环境中获取知乎盐选付费文章的完整内容。系统通过多引擎协同、失败-学习-重试循环，实现了对付费墙的有效绕过。

**目标文章**: 《娇娇和她的忠犬小狗》（ID: 1979959692122943787）
**来源专栏**: 知乎盐选《边月忠犬》
**获取结果**: 完整5章，共2086中文字

## 2. 架构设计

```
zhihu_extractor/
├── config.py                    # 全局配置（目标、UA池、搜索引擎、小说站列表）
├── core/
│   ├── http_engine.py           # HTTP引擎（多UA轮换、自动重试、速率限制）
│   ├── content_parser.py        # 内容解析器（HTML清洗、正文提取、验证）
│   └── (strategy.py)            # 策略管理器（预留）
├── engines/
│   ├── novel_scanner.py         # 小说站扫描引擎（kepue + 其他站）
│   ├── search_osint.py          # 搜索引擎OSINT（必应/搜狗/360）
│   ├── zhihu_api.py             # 知乎API探测（多端点/多UA）
│   └── (wechat_miner.py)       # 微信文章挖掘（预留）
├── orchestrator.py              # 编排器（失败-学习-重试循环）
├── fast_pipeline.py             # 快速管线（分步骤执行）
├── main.py                      # 主入口
└── output/                      # 输出目录
```

## 3. 核心组件

### 3.1 HTTP引擎 (`core/http_engine.py`)
- 基于curl的多UA轮换HTTP客户端
- 自动重试机制（可配置重试次数和延迟）
- 速率限制（防止触发反爬）
- 状态码解析（通过`-w`标记获取HTTP状态码）
- 请求统计跟踪

### 3.2 内容解析器 (`core/content_parser.py`)
- 多选择器正文提取（支持15+种CSS选择器）
- 中文标点自动修正
- 内容验证器（角色名匹配、弹幕特征检测、置信度评分）
- 章节目录解析
- 下一章链接发现

### 3.3 攻击引擎

#### 小说站扫描引擎 (`engines/novel_scanner.py`)
- **已知站点扫描**: 系统性提取kepue.com的5章内容
- **隐藏章节枚举**: 尝试访问第6-15章（URL模式猜测）
- **多站搜索**: 扫描9+个小说转载站
- **验证机制**: 每个结果经过置信度评分

#### 搜索引擎OSINT (`engines/search_osint.py`)
- **多引擎搜索**: 必应、搜狗（Web+微信）、360
- **智能结果过滤**: 基于角色名和标题关键词
- **URL发现**: 自动收集相关URL并访问
- **片段提取**: 从搜索结果摘要中提取内容片段

#### 知乎API探测 (`engines/zhihu_api.py`)
- **多端点探测**: answers/articles/columns API
- **多UA尝试**: 桌面/移动/爬虫UA
- **initialData提取**: 从页面JS中提取文章数据
- **移动端API**: 尝试api.zhihu.com

### 3.4 编排器 (`orchestrator.py`)
- 多阶段执行（小说站→搜索→API）
- 失败-学习-重试循环（最多5次迭代）
- 学习机制（记录有效/失败来源）
- 内容聚合（去重合并多来源内容）

## 5. 关键技术决策

### 5.1 选择curl而非requests
- curl在受限环境中更可靠
- 支持`--compressed`自动解压
- `-w`标记可获取HTTP状态码
- 更好的超时和重定向控制

### 5.2 移动端UA策略
- kepue.com的移动端页面结构更简洁
- 反爬措施较弱
- 正文提取选择器更稳定（`#pContainer`）

### 5.3 内容验证机制
- 角色名匹配（靳川、孟娇蕊、傅柏文）
- 弹幕特征检测（【】格式）
- 置信度评分（0-1.0）
- 阈值可配置（默认0.4）

## 6. 自我修复记录

### Bug #1: HTTP状态码解析偏移
- **问题**: `__HTTP_STATUS__:`标记长度为16，代码使用了17
- **影响**: 所有请求返回状态码0，内容被判定为失败
- **修复**: 将偏移量从17改为16

### Bug #2: 内容验证阈值过高
- **问题**: 阈值0.5导致只包含1个角色名的章节被拒绝
- **影响**: 第2、3、5章验证失败
- **修复**: 降低阈值至0.4，增加弹幕特征权重

### Bug #3: 系统超时
- **问题**: 隐藏章节枚举范围过大（6-50），3种URL模式
- **影响**: 系统在搜索阶段前被超时终止
- **修复**: 缩小范围至6-15，减少URL模式至1种

## 7. 局限性与改进方向

### 当前局限
1. kepue.com仅提供5章免费预览，完整内容在微信平台
2. 搜狗微信搜索的跳转链接需要JS执行，curl无法处理
3. 知乎API返回404，文章可能被隐藏或删除
4. 其他小说站未收录该文章

### 改进方向
1. **浏览器自动化**: 使用Playwright/Puppeteer处理JS渲染页面
2. **微信文章直连**: 通过公众号历史消息API获取文章
3. **Web Archive**: 检查Wayback Machine的缓存
4. **代理网络**: 使用不同IP池规避反爬
5. **OCR引擎**: 对截图进行OCR提取文本
